# OmniMonitor 0.4.2

This release supersedes v0.4.1. It fixes the menu-bar icon, the mini view that left you in the system browser, "Full stats" opening the website, and most controls that did nothing inside the native app window.

## What's fixed
- **Mini view is a real window.** Before, the full window navigated itself to the mini page, and the only way back was a "Full stats" link that WKWebView handed to the system browser. Mini is now its own compact native window (340×540), with an optional **keep the mini window on top** setting and a **Full window** link. The tray and the stats server are never touched. CI runs a mini smoke and a mini → full switch smoke on macOS and Windows.
- **Mini → full no longer opens the browser.** Closing the mini window to open the full one looked like a crash to the old window's watcher, so it fell back to the browser. Our own terminate is no longer treated as a crash.
- **"Full stats" and tray items open or focus the native window.** The browser opens only from the explicit **Open in browser** item.
- **Controls that did nothing inside the app window.** WKWebView ignores download links, `target=_blank` / `window.open`, and some dialogs and clipboard calls.
  - Exports are saved to ~/Downloads (never overwriting) and revealed in Finder or Explorer.
  - External https links open in the default browser (https only).
  - Copy falls back when the clipboard API is blocked.
  - The tray "show file" on macOS reveals the file (`open -R`) instead of opening it in TextEdit.
- **Empty token stats say why** in a visible banner (for example: no `~/.grok/sessions`, no `updates.jsonl`, unreadable files, or no completed-turn usage yet).
- **Grok session parsing:** turns are deduplicated by Grok's `prompt_id` (forked sessions are not double counted), and turns with only top-level usage (no per-model split) are counted once.

## What's changed
- **New tray icon.**
  - macOS: a crisp 22pt (44 px @2x) template ring that macOS tints for light and dark menu bars. Optional % label via **macOS: show the % next to the ring**. Critical (< 20%) is red.
  - Windows/Linux: a cleaner colored gauge; no digits below 24 px.

## What's new
- **Report a problem.** A sidebar button shows a redacted diagnostics report (version, platform, status, offline doctor checks). No keys, tokens, secret URLs or home paths. You can copy it or save it to Downloads.

## Install or upgrade

Check each download against `SHA256SUMS.txt` (`shasum -a 256 <file>` on macOS, `sha256sum <file>` on Linux, `Get-FileHash <file>` on Windows).

- **macOS:** quit the old OmniMonitor first (menu-bar icon → Quit). Open `omnimonitor-macos-arm64.dmg` (Apple Silicon) or `omnimonitor-macos-x86_64.dmg` (Intel) and drag `omnimonitor.app` onto Applications, replacing the old copy. The same app is attached as a `.zip`.
  - The app is ad-hoc signed only and **not notarized**, so Gatekeeper blocks the first launch: right-click the app → **Open** → **Open**. On macOS 15+, try once, then **System Settings → Privacy & Security → Open Anyway**. Or: `xattr -dr com.apple.quarantine /Applications/omnimonitor.app`.
  - The app lives in the menu bar (no Dock icon); on notched MacBooks the icon can hide behind the notch.
- **Linux (x86_64):** `chmod +x omnimonitor-linux-x86_64.AppImage && ./omnimonitor-linux-x86_64.AppImage` (needs FUSE 2; otherwise add `--appimage-extract-and-run`), or unpack `omnimonitor-linux-x86_64.tar.gz` and run `./omnimonitor`.
- **Windows:** unzip `omnimonitor-windows-x86_64.zip` and run `omnimonitor.exe` (unsigned: SmartScreen → **More info → Run anyway**).
- **After upgrading:** open the app from the menu bar. Try Mini view and **Full window**, and **Report a problem** if something still fails.

## Not verified
- **No real Mac was available for this release.** The Retina look and template tinting of the new menu-bar icon, the always-on-top mini setting, and Finder reveal were checked only via rendered previews and CI (macOS and Windows runners with pywebview).
- Grok session parsing was checked against the public format docs, not against real `~/.grok/sessions` logs.
- Binaries are ad-hoc signed only (macOS) and not notarized; Windows is unsigned.
