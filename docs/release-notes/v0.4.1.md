# OmniMonitor 0.4.1

This release supersedes v0.4.0. It fixes the app staying on demo (fake) numbers after you install the Grok CLI from the in-app Setup wizard and log in.

## What's fixed
- **In-app Setup switches off demo mode.** The Setup page has a Grok login card: CLI path, login state, the exact login command (login is interactive, so run it in Terminal), a Re-check button, and **Use my real Grok usage**. That button reads your Grok usage first and switches the app to it only if the read works.
- **Config reload.** The running app picks up `config.json` changes (for example after `omnimonitor setup` in a terminal) on the next poll or Refresh, without a restart.
- **Poll logging.** Every poll is logged with the source, % remaining or the error, and how long it took; Refresh clicks and the app window process are logged too (`~/Library/Logs/OmniMonitor/omnimonitor.log` on macOS).
- **`omnimonitor doctor` shows the running app.** It reports the configured source honestly (it used to show `grok_cli_billing` even when the config said `demo`) and adds a "running app" section (source, % remaining, last poll, last error, Grok CLI path) that flags any mismatch with the config.
- **Clearer "tokens not available".** Grok token stats appear once the Grok CLI writes `~/.grok/sessions`; if `~/.grok/logs/unified.jsonl` exists the message points to the experimental unified-log provider (don't enable both: turns would count twice).

## Install or upgrade

Check each download against `SHA256SUMS.txt` (`shasum -a 256 <file>` on macOS, `sha256sum <file>` on Linux, `Get-FileHash <file>` on Windows).

- **macOS:** quit the old OmniMonitor first (menu-bar icon → Quit). Open `omnimonitor-macos-arm64.dmg` (Apple Silicon) or `omnimonitor-macos-x86_64.dmg` (Intel) and drag `omnimonitor.app` onto Applications, replacing the old copy. The same app is attached as a `.zip`.
  - The app is ad-hoc signed only and **not notarized**, so Gatekeeper blocks the first launch: right-click the app → **Open** → **Open**. On macOS 15+, try once, then **System Settings → Privacy & Security → Open Anyway**. Or: `xattr -dr com.apple.quarantine /Applications/omnimonitor.app`.
  - The app lives in the menu bar (no Dock icon); on notched MacBooks the icon can hide behind the notch.
- **Linux (x86_64):** `chmod +x omnimonitor-linux-x86_64.AppImage && ./omnimonitor-linux-x86_64.AppImage` (needs FUSE 2; otherwise add `--appimage-extract-and-run`), or unpack `omnimonitor-linux-x86_64.tar.gz` and run `./omnimonitor`.
- **Windows:** unzip `omnimonitor-windows-x86_64.zip` and run `omnimonitor.exe` (unsigned: SmartScreen → **More info → Run anyway**).
- **After upgrading:** open Setup in the app and click **Use my real Grok usage**, then check `omnimonitor doctor` (macOS: `/Applications/omnimonitor.app/Contents/MacOS/omnimonitor doctor`).
- **Staying on v0.4.0 and stuck on demo?** Run `omnimonitor setup` in Terminal (macOS: `/Applications/omnimonitor.app/Contents/MacOS/omnimonitor setup`), then quit and reopen the app.

## Not verified
- **The fix has not been run on a real Mac or with a real Grok account.** The diagnosis (the app stayed in demo mode) comes from reading the code and the reporter's log; it is covered by automated tests with mocked billing only.
- The "Use my real Grok usage" button, config reload and the doctor "running app" section have been tested only in CI (macOS, Windows, Linux runners), not by a person in the app window.
- Binaries are ad-hoc signed only (macOS) and not notarized; Windows is unsigned.
